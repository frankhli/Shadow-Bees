# 任务：跳海Global游客端改造方案（质的提升）

## 任务ID
TIAOHAI-TRANSFORM-001

## 项目背景
- 现有网站：/home/node/workspace-host/tiaohai-global/（已完成70-80%）
- 参考PRD：/home/node/workspace-host/Shadow-bees海外版.docx
- 当前问题：Demo感强、不真实、体验不理想
- 目标：质的提升（不是小修小补，是显著改进）

## 改造原则
1. **非重做** — 基于现有代码改造，不从头开发
2. **可大动** — 页面结构、功能、流程都可以改
3. **质的提升** — Frank再看时，明显感觉"完全不同"

## 专家评估维度

### 1. 商业逻辑评估（Frank主导）
- 当前商业模式是否清晰？
- 站内预订 vs 跳转Booking，优先级？
- AI客服的差异化价值是否体现？
- 变现路径是否顺畅？

### 2. 行业惯例评估（hospitality_expert）
- 外国人预订中国酒店的核心痛点是否解决？
- 信息展示是否符合OTA标准？
- 信任建立机制是否到位？
- 与Booking/Airbnb的差距在哪里？

### 3. 用户体验评估（designer + product_manager）
- 首页信息架构是否合理？
- 酒店详情页是否促进转化？
- 预订流程是否顺畅？
- 移动端体验是否优化？

### 4. 视觉设计评估（ui_designer）
- 如何摆脱"Demo感"？
- 如何建立"真实感"和"专业感"？
- 图片、颜色、字体如何提升？

### 5. 功能完整性评估（architect）
- 现有功能是否完整？
- 哪些功能缺失或鸡肋？
- 技术实现难度评估

## 需要回答的核心问题

### 页面层面
1. **首页** — 需要大改吗？怎么改？
2. **酒店列表页** — 筛选、排序、展示方式优化？
3. **酒店详情页** — 信息优先级、图片展示、预订CTA？
4. **预订流程** — 几步完成？需要简化吗？
5. **AI客服** — 入口、交互、功能完善？

### 功能层面
1. **搜索功能** — 是否需要加强？
2. **筛选功能** — 筛选条件是否合理？
3. **地图功能** — 是否需要？
4. **收藏/对比** — 是否需要增加？
5. **支付功能** — 站内支付 vs 跳转，怎么设计？

### 体验层面
1. **信任建立** — 如何让外国人相信这个网站？
2. **信息完整性** — 哪些信息缺失？
3. **真实感** — 如何摆脱Mock数据感？
4. **差异化** — 和Booking比，独特价值是什么？

## 输出要求

### 每个专家输出
1. **当前问题清单** — 具体问题（附截图/代码位置）
2. **改造建议** — 具体怎么改（附参考案例）
3. **优先级** — P0必须改 / P1建议改 / P2可以不改
4. **工作量预估** — 大改 / 中改 / 小改

### 整合输出
1. **改造总方案** — 哪些页面大改、哪些小改、哪些不动
2. **功能变更清单** — 新增功能、删除功能、优化功能
3. **版本规划** — 分几期完成？每期做什么？
4. **预期效果** — 改完后的用户体验描述
